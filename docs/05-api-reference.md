All endpoints sit behind Cloud Run IAM: every request needs `Authorization: Bearer <Google ID token>` from an identity holding `roles/run.invoker`. A machine-readable OpenAPI 3.0.3 document is served at `GET /openapi.json`.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Service status and endpoint registry |
| `GET` | `/discovery` | Policy-filtered model catalog |
| `GET` | `/openapi.json` | OpenAPI 3.0.3 specification |
| `POST` | `/v1/projects/{project}/locations/{region}/publishers/{publisher}/models/{model}:{action}` | Vertex AI inference (Gemini, Claude) |

The proxy is meant for non-browser clients and sends no CORS headers.

## `GET /health`

```json
{
  "status": "healthy",
  "service": "copilot-chat-proxy",
  "runtime": "python-3.14",
  "allowed_regions": ["global"],
  "endpoints": { "discovery": "/discovery", "openapi": "/openapi.json", "health": "/health" }
}
```

## `GET /discovery`

Returns the catalog described in [Governance](04-governance.md#discovery-catalog):

```json
{
  "regionPriority": ["global"],
  "candidateModels": [
    {
      "id": "gemini-3.8-flash",
      "vendor": "google",
      "displayName": "Gemini 3.8 Flash",
      "family": "gemini",
      "version": "gemini-3.8-flash",
      "maxInputTokens": 250000,
      "maxOutputTokens": 65536,
      "capabilities": { "imageInput": true, "toolCalling": true },
      "effort": { "values": ["low", "medium", "high"], "default": "medium" },
      "pricing": { "input": 0.75, "output": 3.75 }
    }
  ]
}
```

`effort` is optional and is returned whenever the catalog declares it; clients do not need a capability header. Its values and default come from the configured catalog. The example above illustrates the shape; use the live response for current choices.

## `POST /v1/projects/.../models/{model}:{action}`

The path and body are the native Vertex AI REST contract, so the official SDKs work by pointing their base URL at the proxy. Typical actions are `generateContent`, `streamGenerateContent` (Gemini) and `rawPredict`, `streamRawPredict` (Claude).

- The project, region and publisher come from the path; `{model}` must equal an allowed catalog entry's literal backend `version` for that publisher.
- Client labels: Gemini in `labels` (or `config.labels`) in the body; Claude in the `X-Vertex-AI-Labels` header (base64 JSON). See [Governance](04-governance.md).
- Effort uses Gemini's `generationConfig.thinkingConfig.thinkingLevel` or Claude's `output_config.effort`; omission applies the catalog default. Invalid effort is rejected before any upstream request. Explicit `countTokens` requests do not validate or inject effort.
- On success the upstream status, `Content-Type` and body are relayed unchanged. Streaming responses (`text/event-stream` or chunked JSON) are forwarded chunk by chunk.
- Upstream errors (4xx/5xx from Vertex AI) are passed through with their original status and body.

Only `/v1/projects/...` is an inference path. Other shapes (`/projects/...`, `/predict`, `/models.json`) return `404`.

## Error format

Errors generated by the proxy use a Google-style JSON envelope:

```json
{
  "error": {
    "code": 400,
    "status": "FAILED_PRECONDITION",
    "message": "Missing required label 'vscode-vertex-ai-project'."
  }
}
```

| HTTP | `status` | Cause |
| --- | --- | --- |
| 400 | `FAILED_PRECONDITION` | Model/publisher not authorized, project or region not allowed, invalid effort, missing required label, or context limit exceeded (the last also returns `context_tokens` and `max_context_tokens`) |
| 401 | `UNAUTHENTICATED` | Missing, malformed, expired or invalid token; wrong issuer or audience; no `email` claim |
| 404 | `NOT_FOUND` | Unknown path |
| 405 | `METHOD_NOT_ALLOWED` | Wrong HTTP method for a known path (for example `POST /health` or `GET` on an inference path) |
| 502 | `BAD_GATEWAY` | The proxy could not reach Vertex AI |

Calls rejected by Cloud Run IAM before reaching the container return `401`/`403` from Google's front end, with Google's error page rather than this envelope.

Governance and authentication failures are deterministic: clients should show the message and not retry.
